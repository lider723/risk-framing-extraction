# 给协作者

## 最终目的

研究新闻如何呈现AI风险。希望借助LLM，以可复核的原文证据识别不同风险，再编码风险类型、受影响对象、行动者／致因、道德评价和应对措施等变量。四项framing功能的操作定义以本仓库编码手册为准，不在这份简介另创定义。

当前只解决提取，后续编码暂缓。先看 [真实错例](ERROR_CASES.md) 和 [两轮结果](STATUS_2026-10-25.md) 即可；不必从历史编码手册开始。

提取的一个单元是相对独立的“AI相关因素—具体负面后果—文章支持的联系”主张，**不是一句话，也不是一个MIT类别**。同一句可以含两个独立风险，同一风险也可以跨段落出现多次。

## 当前流程和评价标准

v5原始流程为 Call1发现、Call2补漏、Call3确认与组织证据；Call3由控制器按context_requests回填原文并继续审阅。每个发现阶段可能因文章分块有多次调用，确认也可能有多轮，并非每篇固定3次请求。完整原文仍是后续编码语境。

提取结果不必和人工摘句逐字相同。如果仍指向同一风险，全文能补齐关联证据，而且不会因差异丢失独立风险、混淆主体／归属／条件，则可视为内容对应。引用本身必须是原文逐字片段；“引用逐字”不等于“预测句必须和Gold摘句完全相同”。

严格一对一P/R/F1、风险内容覆盖、重复、异质混合、无依据纳入、归属／条件错误必须分开看。一次预测覆盖两类风险可能内容都覆盖，却仍不适合作为一个编码单元。格式失败不能当“无风险”。

## 已观察到的问题

1. **额外加门槛**：原文已呈现有归属的创造力威胁，模型仍要求更具体的下一层损害；人的AI使用／滥用也可能被误排除。
2. **拆不开**：同候选有抄袭与虚假新闻，或岗位消失与自主战争，常被压成一个复合单元。
3. **并不拢**：同一风险的概括、实例、反应和治理建议，被当成多个风险。
4. **误提**：中性的AI计划、能力描述、泛泛风险评价，有时被补写成独立负面后果。
5. **回归**：某些Prompt少输出了很多条，看似精确率提升，实际把独立有效风险一起漏掉。
6. **不稳定**：温度0，同样实际首轮消息仍可能确认／拒绝不一致。

## 重点审阅

- 是任务定义、示例字段、阶段职责还是输出契约的哪一层出了问题？给具体证据，不预设“多给例子”“写CoT”“拆成多次”一定有效。
- 是否有字段或示例暗中教了错误的一候选一单元关系？反例是否真对应研究边界？
- 如何分开“确认一个主张成立”和“把同一风险组织到一起”，同时避免上一步错误被永久锁死？
- 如何安排最小、同样本、同Gold的对照，并确保原本正确的正例和阴性不被改坏？
- 哪些应交给程序校验，哪些仍需要研究者对原文进行语义判定？
