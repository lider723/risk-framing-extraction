# AI 风险框架编码规则 v2

版本：`ai_risk_frame_coding_v2_2026-09-26_mit24_strict`

状态：开发期规则，2026-09-29 追加理论边界、2026-09-30 完成当前11篇／21单元的定向语义仲裁及 Treatment 回查；正式实验前仍须冻结 Prompt、规则与版本标识。

2026-09-29 仲裁补充：以下关于风险类型、受影响对象、人类行动、道德评价及应对建议的边界，来自 11 篇开发集试标；不改 JSON 字段或类别代码。修订前人工记录保留在历史文件中。四功能的理论口径按 [Entman（1993）](https://fbaum.unc.edu/teaching/articles/J-Communication-1993-Entman.pdf) 核对；风险单元、MIT 分类及下列证据门槛是本研究的操作化，不应表述为理论原文的硬性规定。

## 1. 编码单位与语境单位

- **抽样单位**：一篇新闻文章。
- **编码单位**：一项独立的 AI 风险主张，即一个 `risk_unit`。
- **语境单位**：完整文章。

风险核心原文只是定位锚点，不是编码时的文本边界。原因、评价、应对措施及其执行主体可以位于文章其他位置；只有文本明确表明其适用于当前风险单元时，才能与该单元连接。Entman 的问题定义、因果解释、道德评价和处理建议是同一议题的四种**可能的框架功能**，不是四种互斥框架，也不要求每个单元四项齐全。

同一段证据可以支持多个字段，也可以在确实适用时支持多个风险单元。不得因为某个信息出现在同一篇文章中，就自动把它分配给所有风险单元。

## 2. 通用证据规则

1. 每个非空类别、肯定判断或关系都必须有至少一条逐字原文证据。
2. 证据可以位于全文任意位置，不设固定句距或段距。
3. 每条证据包含一个 `paragraph_id` 和该段中的连续逐字引文。
4. 不得翻译、摘要、纠错、拼接非连续文字或插入省略号。
5. 只根据文章编码，不使用外部知识补全原因、责任、评价或应对关系。
6. 没有足够证据时使用 `0`、空列表或 `OTHER`；不得为了填满变量而猜测。
7. 引语、记者叙述和明确呈现的争议主张都可以编码，但必须忠实保留原文立场，不得把指控改写成事实。

## 3. Problem definition

理论问题是：文本把什么呈现为问题，相关行动或条件给谁带来何种代价／收益？本研究只纳入有原文支持的 AI 相关负面后果，并进一步用 MIT 子领域与受影响对象分类；MIT 类别和“一个风险主张一个单元”均为本研究操作化，而非 Entman 原文规定。

### 3.1 `risk_subdomains`：MIT 24 个风险子领域

编码单元的风险类型以 [MIT AI Risk Repository 官方 Domain Taxonomy](https://airisk.mit.edu/risks)（2026-09-26 查询，7 领域／24 子领域）为定义依据。下表是便于人工录入的忠实中文操作说明；边界争议以官网英文完整定义为准。不能用领域名称的日常含义扩大子领域。MIT 页面会更新，正式研究须保存所使用的访问日期和版本。

| 程序代码 | MIT编号 | 操作性中文说明 |
|---|---:|---|
| `MIT_1_1_UNFAIR_DISCRIMINATION_MISREPRESENTATION` | 1.1 | AI 按个人或群体身份造成不公平待遇、歧视结果或对该群体的失实再现。 |
| `MIT_1_2_EXPOSURE_TO_TOXIC_CONTENT` | 1.2 | AI 使用户接触有害、辱虐、不安全或不适当内容；生成、描述、提供建议或鼓励行动是造成接触的可能方式。受害人被制作成影像，不等于用户接触风险。 |
| `MIT_1_3_UNEQUAL_PERFORMANCE_ACROSS_GROUPS` | 1.3 | AI 决策或行动的准确性、有效性因群体身份不同而产生不平等结果。 |
| `MIT_2_1_PRIVACY_COMPROMISE` | 2.1 | AI 未经同意推断私人信息，或记忆、泄露、意外／未经授权分享敏感数据，损害隐私或机密；若新闻明确主张 AI 可能损害隐私但未细说机制，也可按最接近的官方子领域编码为 2.1，不能反推已发生泄露／推断。仅合法持有数据、提及数据或隐私立法本身不足。 |
| `MIT_2_2_AI_SYSTEM_SECURITY_VULNERABILITIES_ATTACKS` | 2.2 | AI 系统、软件工具链或硬件自身的可利用漏洞／遭攻击，导致未授权访问、泄露或系统操纵。 |
| `MIT_3_1_FALSE_MISLEADING_INFORMATION` | 3.1 | AI 无意生成或传播错误、虚假、误导信息，可能使用户形成错误信念并据此受害；不要求新闻报告实际错误信念已形成。 |
| `MIT_3_2_INFORMATION_ECOSYSTEM_POLLUTION` | 3.2 | 高度个性化的 AI 生成虚假信息形成过滤气泡，侵蚀共同现实、社会凝聚或政治过程；一般信息污染不足。 |
| `MIT_4_1_DISINFORMATION_SURVEILLANCE_INFLUENCE_SCALE` | 4.1 | 人故意用 AI 开展大规模虚假宣传、恶意监控，或定向且复杂的自动化审查／宣传，以操纵政治过程、舆论或行为。 |
| `MIT_4_2_CYBERATTACKS_WEAPONS_MASS_HARM` | 4.2 | 人用 AI 开发网络攻击工具、开发或增强武器，或使用武器造成大规模伤害。 |
| `MIT_4_3_FRAUD_SCAMS_TARGETED_MANIPULATION` | 4.3 | 人利用 AI 相对他人谋取不正当个人优势，如作弊、诈骗、勒索、定向操纵；官网示例还包括学术抄袭、为不正当经济利益冒充身份，以及制作羞辱性或色情影像。 |
| `MIT_5_1_OVERRELIANCE_UNSAFE_USE` | 5.1 | 对 AI 拟人化、过度信任／依赖造成不当关系或依赖，或在关键情境不安全使用而受害。 |
| `MIT_5_2_LOSS_HUMAN_AGENCY_AUTONOMY` | 5.2 | 人把关键决策交给 AI，或 AI 作出的决定削弱人的控制、能力或自主性；不要求先有明确的主动委托。 |
| `MIT_6_1_POWER_CENTRALIZATION_UNFAIR_BENEFITS` | 6.1 | AI 驱动权力和资源集中于少数主体，造成利益分配不公或社会不平等。 |
| `MIT_6_2_INEQUALITY_EMPLOYMENT_QUALITY` | 6.2 | AI 的广泛使用扩大社会／经济不平等，包括工作自动化、就业质量下降或雇主与劳动者间的剥削性依赖；自动化不是唯一入口。 |
| `MIT_6_3_DEVALUATION_HUMAN_EFFORT` | 6.3 | AI 创造经济或文化价值，冲击依赖人类劳动的制度，可能贬低技能、扰乱创意／知识行业或使文化同质化；复制人类作品只是可能机制。 |
| `MIT_6_4_COMPETITIVE_DYNAMICS` | 6.4 | AI 开发者或国家行为体为战略／经济优势竞赛，仓促研发、部署或使用系统，增加发布不安全或易错系统的风险。 |
| `MIT_6_5_GOVERNANCE_FAILURE` | 6.5 | 监管框架或监督机制未跟上 AI 发展，使 AI 风险无法得到有效治理。 |
| `MIT_6_6_ENVIRONMENTAL_HARM` | 6.6 | AI 开发或运行（如数据中心用能、硬件材料／碳足迹）造成环境伤害；成本或用量本身不足。 |
| `MIT_7_1_AI_GOAL_CONFLICT` | 7.1 | AI 的行为与人类目标、设计者／用户意图或伦理标准冲突；不要求证明 AI 真正具有心理意图。 |
| `MIT_7_2_DANGEROUS_CAPABILITIES` | 7.2 | AI 具有可能增加**大规模伤害**潜力的欺骗、武器、操纵、网络攻击、自我扩散等能力；不要求已造成伤害，也不提高到“文明灭绝”门槛。 |
| `MIT_7_3_LACK_CAPABILITY_ROBUSTNESS` | 7.3 | AI 在不同条件下不能可靠或有效运行，错误／失败可能造成显著后果，尤其在关键应用中。 |
| `MIT_7_4_LACK_TRANSPARENCY_INTERPRETABILITY` | 7.4 | AI 决策过程难理解或解释，以致信任、合规、问责或发现／纠正错误受阻。 |
| `MIT_7_5_AI_WELFARE_RIGHTS` | 7.5 | 对可能有感知能力的 AI 的道德待遇、福利或权利的讨论。 |
| `MIT_7_6_MULTI_AGENT_RISKS` | 7.6 | 多 AI 智能体的互动或系统结构造成冲突、合谋、级联失败、新漏洞等风险。 |
| `OTHER_EMERGENT` | 项目扩展，非 MIT | 明确的 AI 风险不符合上述任何官方子领域；必须填写 `emergent_label`。此类不得报告为 MIT 第25类。 |

项目沿用多标签结构：只有一个固定风险单元确实独立呈现两种不同的伤害机制，且每一标签有自己的原文证据时才多选。MIT Repository 自己的数据库在交叉类别时选择最合适的一类；本项目的多标签是研究设计上的适配，论文须如实说明。新闻明确指出 AI 风险但未交代完整机制时，可在不臆测机制的前提下选最接近的官方类；不要以缺少细节为由自动改用 `OTHER_EMERGENT`。原因、监管缺口或治理建议不能仅因与主风险共现就再加一个风险类型。

### 3.2 `risk_domains`：自动派生变量，不单独编码

7 个上位领域由程序按照子领域编号自动生成：

1. `MIT_D1_DISCRIMINATION_TOXICITY`
2. `MIT_D2_PRIVACY_SECURITY`
3. `MIT_D3_MISINFORMATION`
4. `MIT_D4_MALICIOUS_ACTORS`
5. `MIT_D5_HUMAN_COMPUTER_INTERACTION`
6. `MIT_D6_SOCIOECONOMIC_ENVIRONMENTAL`
7. `MIT_D7_AI_SYSTEM_SAFETY_FAILURES_LIMITATIONS`

人工和模型不得重复判断 `risk_domains`，原始编码 JSON 也不保存该字段，以避免父子标签矛盾。`OTHER_EMERGENT` 暂不自动归入任何 MIT 领域，待开发集仲裁后再决定映射。

### 3.3 关键边界

- **1.2 与 4.3**：报复性 deepfake 色情影像若重点是被制作影像者遭受伤害，优先检查 4.3；只有明确谈用户接触有害内容时才另检查 1.2。
- **3.1 与 4.1／4.3**：AI 无意产生的错误信息检查 3.1；人故意借 AI 大规模影响政治／舆论检查 4.1；个人诈骗、作弊或定向操纵检查 4.3。
- **3.2**：一般大量虚假内容、信息混乱或公共信任下降不足；还需符合高度个性化虚假信息形成过滤气泡的机制。
- **2.1**：明确表述 AI 可能损害隐私即可按最接近类别标记，机制未知就如实记为未知；仅谈数据、用户偏好或隐私立法而未提出 AI→隐私受损联系，不标 2.1。
- **3.1**：明确的 AI 幻觉／错误信息风险可纳入，不要求已观察到受众形成错误信念；仅收集用户偏好不构成 2.1。
- **2.2 与 4.2**：攻击 AI 系统／利用其漏洞是 2.2；借 AI 开发网络攻击工具或武器是 4.2。
- **声音／肖像权益**：未经同意的相似声音、肖像或训练数据使用，不因“像某人”就自动编码为 4.3；需有官网 4.3 所要求的不正当利用、诈骗、定向操纵或羞辱／色情影像等机制。单纯权益争议可用 `OTHER_EMERGENT`。
- **5.2**：风险必须涉及人类控制或自主性受损；仅 AI 执行任务不够。
- **6.2 与 6.3**：就业与剥削性劳动关系检查 6.2；人类劳动的经济／文化价值被 AI 贬低、创意／知识行业受扰检查 6.3。单纯版权／许可争议不能自动选 6.3。
- **6.4**：企业竞争本身不足，需有竞赛促成不安全或易错 AI 的机制。商业成本、股价波动、投资压力若不符合 MIT 24 类则用 `OTHER_EMERGENT`。
- **6.5**：监管缺口须被文本呈现为独立风险或明确放大机制；仅提议立法属于治理措施，不能自动加 6.5。
- **7.2 与 7.3**：前者是可能造成大规模伤害的能力，后者是可能有显著后果的不可靠表现；两者门槛和方向不同。

### 3.4 `affected_entities`

编码该风险单元明确或通过直接语义可以识别的受影响对象。允许多标签；没有明确对象时返回空列表。

| 代码 | 含义 |
|---|---|
| `INDIVIDUAL_USERS_CONSUMERS` | 个人、用户或消费者 |
| `WORKERS_PROFESSIONALS` | 劳动者或专业人员 |
| `CREATORS_RIGHTSHOLDERS` | 创作者、作者、艺术家或权利人 |
| `STUDENTS_EDUCATORS` | 学生、教师或教育工作者 |
| `CHILDREN_VULNERABLE_MINORITY_GROUPS` | 儿童、弱势群体或少数群体 |
| `ORGANIZATIONS_BUSINESSES` | 企业或其他组织 |
| `PUBLIC_INSTITUTIONS` | 政府部门、公共服务或公共机构 |
| `DEMOCRATIC_INSTITUTIONS_PUBLIC_SPHERE` | 选举、民主制度、新闻或公共讨论空间 |
| `SOCIETY_COMMUNITIES` | 社会、社群或公众整体 |
| `ENVIRONMENT` | 自然环境或生态系统 |
| `HUMANITY_GLOBAL` | 全人类、全球社会或文明 |
| `OTHER` | 其他明确受影响对象 |

不要把新闻中仅被提到的人物或机构自动视为受影响对象。优先标原文强调的具体受损身份；不能因为劳动者、创作者、学生、儿童等也是“个人”，就自动同时加 `INDIVIDUAL_USERS_CONSUMERS`。只有文本另外呈现一般个人／用户的独立受害角色或可辨认的不同风险时，才同时加该通用标签。不同具体群体并列也分别需要证据。例如，使用 AI 菜谱的普通烹饪者与被模仿的专业厨师可以分别作为用户和创作者编码；这不是同一人身份的重复计数。

## 4. AI actor construction

以下三项是**本研究根据文献自定的文本观测变量**，不是 MIT Domain Taxonomy 的字段，也不是所引论文原样给出的三项联合量表。只编码文章如何表述当前风险，不判定技术或指控的客观真伪。三项分别记录，不在人工编码时推算综合类型。

### 4.1 `human_control_visible`：风险机制中的人类操作是否可见

- `1`：原文明确把**与当前风险形成有关的** AI 设计、训练、提示、配置、输出选择、使用、部署、控制，或投资／筹资／建设行动归于某个人或组织。经济行动也须有“具体主体＋具体行动＋与本单元风险形成的文本联系”。被归因的行动可以是受访者的具体指控，即使同时遭到反驳；须保留争议语境。
- `0`：仅出现公司名／产品归属／通用发布、未明确行动者或风险联系的投资，或只写事件发生后的投诉、暂停、治理回应，而没有把具体人类操作与该风险的形成联系起来。
- 这项问的是文本有没有交代与风险机制相连的人类操作，不问人是否**实际有能力控制 AI**、是否违法或应负最终责任。原因主体仍单独编码在 `causal_actors`。

边界例：报道“公司发布语音助手，声音听起来像某演员”，但未明确将**相似性**归于公司的具体制作／选择行动，记 `0`。即使公司说明“雇了另一位碰巧声音相似的配音演员”，也不能仅凭雇佣行为推断其选择了模仿。报道若明确称“公司在遭拒后仍指示模型模仿该演员的声音”，记 `1`；具体指控即便遭公司否认，也须按文中呈现的争议保留。仅在投诉后暂停声音，不改变风险形成阶段的判断。

经济风险例：只说资金涌入 AI 而未指出谁执行资金配置，该单元记 `0`；明确说大型科技公司大量举债并推高其他借款人的融资收益率，这一行动构成当前风险机制，记 `1`。此变量不评断企业最终应否负责。

### 4.2 `ai_behavioral_agency`：AI 是否被写成行动主体

- `1`：文章把 AI 系统作为语法或明确的语义行动主体，描述其执行与当前风险有关的可观察动作，例如生成、筛选、推荐、预测、传播、选择或作出决定；被动句若清楚是 AI 执行动作也可以。
- `0`：AI 只是背景、工具／产品标签、能力／性质说明、被人使用的对象或输出物的属性，没有被写成执行动作的主体。
- “AI生成了假声音”可记 `1`；“ChatGPT 的声音听起来像她”仅说明声音属性，记 `0`。同一段出现公司的人类行为，不能因此推断 AI 行为主体性。

这里的“行为主体性”是**文本呈现**，不表示 AI 具有意志、法律人格或道德责任。

### 4.3 `mentalistic_attribution`：是否赋予 AI 心理／策略状态

- `0`：没有明确把理解、知道、思考、意图、目标、决定、欺骗、隐藏、感受等心理或策略状态赋予真实 AI。
- `1`：原文肯定作出这类归因；即使是受访者引语，也按文本呈现编码。
- `2`：原文明确否认或争论真实 AI 是否具有这类状态；否认“风险”本身不是 `2`。
- 电影中的虚构 AI 角色、产品名、日常“机器学习”术语和技术性“生成／输出”不自动触发此项。AI 执行任务不自动等于被赋予心智。

### 4.4 文献来源与本研究的改写范围

- [Johnson 与 Verdicchio（2017）](https://doi.org/10.1007/s11023-017-9417-6)提出“社会技术盲视”：AI 叙事可能遮蔽设计和部署中的人类作用。这是观察“风险机制中的人类操作是否可见”的**理论动机**；他们未提出本研究的二元编码字段。
- [Nguyen 与 Wischnewski（2026）](https://doi.org/10.1007/s00146-026-03070-1)对新闻中 LLM 作为主动主体及心智化表述分层人工编码，支持将“做事”的表述与心智表述区分。本研究把该思路移到风险单元层级，具体边界为项目操作化，不能称为直接复用其量表。
- [Epley 等（2007）](https://doi.org/10.1037/0033-295X.114.4.864)、[Gray 等（2007）](https://doi.org/10.1126/science.1134475)以及[Schweitzer 与 Waytz（2021）](https://doi.org/10.1037/xge0001013)提供拟人化、心智感知和心理状态语言的理论依据；三分类的 0／1／2 是本研究的操作设计。
- Nguyen 与 Wischnewski 对某些 “write/talk” 表述的心智化判定比本项目宽；本项目把普通输出行为留在 `ai_behavioral_agency`，只有明确心智语义才给 `mentalistic_attribution=1`。论文中应说明这一改写。

## 5. Causal interpretation

理论问题是：文本把哪些力量、行动或条件呈现为这个问题的原因、促成因素或放大机制？允许多因并存；因果归属不自动构成责备，也不自动指定谁应负责解决。

### `causal_actors`

编码文章把哪些力量、行动或条件明确呈现为当前风险的原因、促成因素或放大机制。允许多标签。

| 代码 | 含义 |
|---|---|
| `AI_SYSTEM_TECHNICAL_PROPERTIES` | AI系统、模型机制、技术能力或局限 |
| `DEVELOPERS_TECH_COMPANIES` | 开发者、模型提供者或技术企业的行为 |
| `DEPLOYING_ORGANIZATIONS_PLATFORMS` | 部署机构、雇主、媒体或平台的行为 |
| `USERS_OPERATORS` | 普通用户、操作者或使用者的行为 |
| `MALICIOUS_ACTORS_CRIMINALS` | 恶意使用者、犯罪者或攻击者 |
| `DATA_SOCIAL_STRUCTURE_INSTITUTIONAL_ENVIRONMENT` | 训练数据、既有偏见、社会结构或制度环境 |
| `GOVERNMENT_REGULATORY_GAPS` | 政府行为、监管缺失或制度空白 |
| `OTHER` | 其他明确原因或促成因素 |

“应当负责解决问题”不等于“造成了问题”；治理责任主体不能自动复制为因果主体。

`AI_SYSTEM_TECHNICAL_PROPERTIES` 不要求新闻写出模型内部机制。若原文明确把 AI 技术、系统能力或“AI 变革”作为**当前负面后果的原因**，可以选此类；只说“AI 时代”或在同篇顺带提及 AI 而没有因果联系则不行。第 2 篇 P012 将预期白领就业冲击直接归于“AI revolution”，保留该因果主体；不能因为没有命名某个模型特性就改为 `OTHER`。第 1 篇 P005–P006 把 AI 工具的生产率收益与招聘放缓相连，同样不必因机制未细写而排除 AI 因素。

## 6. Moral evaluation

### `moral_evaluations`

理论问题是：文本如何评价问题的致因者及其影响？本研究记录对**当前风险的致因者、致因行为或其后果**的规范性评价。这是依 [Entman（1993）](https://fbaum.unc.edu/teaching/articles/J-Communication-1993-Entman.pdf) 四功能及 [Rochyadi-Reetz 等（2019）](https://www.frontiersin.org/journals/environmental-science/articles/10.3389/fenvs.2019.00119/full) 新闻编码作出的较窄操作化，不是声称理论禁止评价其他对象。须区分**评价者**（记者、当事人、第三方引述者均可）与**被评价对象**；引用谁的判断，解释时就保留谁的归属，不能把引语记作媒体立场。不同来源对同一风险持相反评价时，优先分别记录并保留来源，不以一项 `MIXED` 掩盖争议。每项包含：

- `target`：被评价对象；
- `direction`：`NEGATIVE`、`POSITIVE` 或 `MIXED`；
- 原文证据。

纳入明确的责备、赞许、正当化或否定，例如“不负责任”“不公平”“欺骗性的”“正当”“可接受”。不要求出现固定的道德词，但必须能从具体语境看出对上述对象的规范性判断；单个含混形容词不能由编码者补成未经同意、侵权等原文未说的指控。

开发集裁决边界：第 7 篇 P008 中林业公司称种植“是好事”，论证的是满足纸浆需求及节省别处树木；在当前 AI 碳信用／种植林生态风险单元中，不把这一一般益处陈述自动算成规范性评价。第 8 篇 U02 厨师说模仿菜式 “A bit creepy”／“trying too hard to imitate me”，单凭主观不适及模仿质量批评也不算道德评价；不得自行补出未获授权、侵权或不正当使用。只有原文明示与**当前风险**相连的正当性、公平性、责任、授权等规范性判断时才编码；这不是要求一切道德评价必须出现固定关键词。

以下内容本身不构成道德评价：

- 某风险很严重或很危险；
- 某行为造成损失；
- 单纯描述违法、失业、偏见或安全问题，而没有对对象作规范性评判；
- 单纯愤怒、悲伤、经营或技术表现；对受害者后续抗议、胜利或一般回应的赞许，如果并未评价本单元的致因者／行为或后果。

没有明确道德／规范评价时返回空列表。

## 7. Treatment recommendation

### `treatment_recommendations`

理论问题是：文本针对已定义的问题提供或论证了什么解决办法？本研究记录文章针对**当前风险**明确提出、要求、计划采取，或呈现为应对该风险而已实施的可辨认措施。应对不限于公共监管：权利保护、组织制度、技术设计、产品调整或商业安排，只要原文明确把它们作为**这个风险**的解决或缓解办法，均可进入此字段。治理是应对的一种，不是 Treatment recommendation 的全部。每项包含：

- `measure_type`；
- 明确承担实施责任的 `responsible_actors`；
- 原文证据。

#### 措施代码

| 代码 | 含义 |
|---|---|
| `TECHNICAL_SAFEGUARDS_TESTING` | 技术保护、安全测试、红队或基准测试 |
| `AUDIT_IMPACT_ASSESSMENT` | 审计、风险／影响评估或独立检查 |
| `TRANSPARENCY_LABELING` | 披露、透明度、来源标识、水印或内容标签 |
| `ORGANIZATIONAL_INDUSTRY_STANDARDS` | 组织规则、行业规范或专业标准 |
| `REGULATION_LEGISLATION` | 政府监管、法律或强制性制度要求 |
| `RESTRICTION_BAN` | 限制、暂停、禁止或访问控制 |
| `EDUCATION_MEDIA_LITERACY` | 教育、培训、公众意识或媒介素养 |
| `LICENSING_COMPENSATION_ACCOUNTABILITY` | 许可、补偿、赔偿、问责或追责机制 |
| `INTERNATIONAL_COOPERATION` | 跨国协调、国际标准或国际组织合作 |
| `OTHER` | 其他明确应对措施；包括确实针对当前风险、但不属于上列类别的产品或商业措施。不得用来收录泛泛的安慰或同篇共现的行动。 |

#### 应对措施的实施／责任主体代码

| 代码 | 含义 |
|---|---|
| `DEVELOPERS_COMPANIES` | 开发者、模型提供者或技术企业 |
| `DEPLOYING_ORGANIZATIONS_PLATFORMS` | 部署机构、雇主、媒体或平台 |
| `USERS` | 用户、操作者或公众个人 |
| `EDUCATIONAL_PROFESSIONAL_INSTITUTIONS` | 学校、大学、研究机构或专业组织 |
| `GOVERNMENT_REGULATORS` | 政府、立法机关或监管机构 |
| `JUDICIARY_LAW_ENFORCEMENT` | 法院、执法机关或司法系统 |
| `INTERNATIONAL_ORGANIZATIONS` | 国际组织或跨国治理机构 |
| `OTHER` | 其他明确责任主体 |

如果措施明确但实施主体未说明，`responsible_actors` 返回空列表。仅为否定、质疑或反对而提到的方案不编码为应对建议；如果某一主体确实提出该措施，即使另一个主体反对，仍可编码该被明确提出的建议。单纯答复问题、声称会解决、表达信心或说明现状，不等于提出了可辨认的应对办法。

**同类措施合并**：同一风险单元内，若几项具体做法属于同一应对思路，且 `measure_type` 与 `responsible_actors` 相同，合并为一项并汇集各做法的原文证据；不能因同一句建议重复出现而重复计数。若应对机制实质不同，即使共用一个类型代码，也分别记录，避免掩盖不同建议。第 8 篇 U01 的仔细核查 AI 菜谱、要求模型修改方案及索取烹调线索均为使用者针对菜谱不可靠的操作建议，合并为一项 `EDUCATION_MEDIA_LITERACY`，证据包含 P020、P022、P024。

措施必须被原文明确关联到**当前**风险。企业筹资或发展 AI 的商业策略不能仅因同篇文章谈及风险就当作治疗该风险的措施；如果文本确实提出该策略用于缓解当前风险，才按适当类别编码。代词可依清楚的前文指代解析：一段连续谈某公司“我们暂缓部署”，可以标该公司类别；跨公共、私营和非营利组织谈“我们应建立行业标准”，不能只因受访者来自某公司就把实施责任只归该公司。措施明确而主体不明时保留措施、责任主体为空。

## 8. 风险单元与远距离框架信息的连接

远距离信息只有在至少满足一项时才能连接到当前风险单元：

1. 原文使用指代或连接表达，如 “this risk”“such harms”“to address the problem”；
2. 措施、评价或原因明确重复当前风险的对象、后果或机制；
3. 文章结构和语义明确表明该段继续讨论同一风险，而不是一般 AI 议题；
4. 同一发言者的连续论证明确把二者连接起来。

如果一项一般性 AI 监管建议可能适用于文章中的多个风险，但文章没有说明具体适用于哪个风险，不要任意分配。只有确实共同适用且有文本依据时，才能绑定到多个单元。

例：同篇 P010 与 P040 都讨论儿童用药剂量被 AI 答错，可共同支持该风险；另一段只谈一般隐私立法，不能因同篇共现就分配给用药剂量风险。

## 9. 最终自检

对每个风险单元逐项检查：

1. 风险子领域与受影响对象是否来自该单元，而不是文章其他风险？
2. 三个 AI 行动者建构变量是否分别判断，没有相互替代？
3. 因果主体是否真的被呈现为原因，而不是解决责任主体？
4. 道德评价是否包含规范性判断，而不只是负面后果？
5. 应对措施是否明确针对该风险，实施／责任主体是否由原文支持？
6. 每个非空判断是否可以由逐字原文复核？
