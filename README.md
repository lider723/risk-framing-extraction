# AI Risk Framing

基于大语言模型辅助内容分析的AI风险新闻研究项目，关注新闻报道如何界定AI风险、呈现行动者，以及解释责任与治理回应。

本仓库包含风险单元提取与框架编码的标注规范、提示词、处理代码和评估材料。目前的开发重点是风险单元提取，包括提示词对照、单元拆分与合并、原文证据校验和误差分析。

## 研究方法

以新闻文章为采样单位，以文章呈现的具体AI风险主张为分析单位。一个风险单元需要有原文依据，明确联系AI相关因素与具体负面后果；同一风险的重复表述合并，不同后果按规则拆分。

风险单元提取采用三个步骤：

1. 发现：分块识别候选风险主张。
2. 补漏：再次检查原文，补充遗漏候选。
3. 确认与整理：结合必要上下文确认主张、拆分或合并单元，并保留原文证据。

提取结果作为后续框架编码的证据锚点，不替代全文语境。框架变量涵盖问题定义、因果解释、道德评价和应对建议，以及风险类型、受影响对象和行动者呈现等维度。

## 使用方式

离线检查需要Python 3.9及以上版本，无需API密钥或额外依赖。在仓库根目录运行：

```sh
python3 scripts/offline_check.py
python3 -m unittest discover -s tests -v
python3 scripts/replay_scores.py
python3 scripts/audit_repo.py
```

模型调用入口为 `scripts/run_extraction.py`，默认仅执行离线预检。实际调用需显式指定 `--run` 和请求上限；依赖、输入格式及运行配置见[技术说明](docs/TECHNICAL_GUIDE.md)。

## 实验与评估

当前以v5为开发基线，对比示例设计、分阶段处理和纳入规则等方案。评估同时报告单元级Precision、Recall、F1、风险内容覆盖及拆合错误，不要求提取片段与人工标注逐字相同。

实验设计、结果与局限见[实验记录](docs/STATUS_2026-10-25.md)。`replay_scores.py`根据已保存的LLM辅助语义复核记录重算匹配与指标，不执行新的模型判断。现有开发集结果不等同于独立测试集表现或下游变量编码准确率。

## 数据说明

受新闻数据使用范围限制，仓库不提供新闻全文、含原文引文的完整人工标注、完整模型请求与响应或未使用的保留集。公开材料包括合成示例、案例概述、去引文评估记录及来源校验信息。真实数据和API密钥应保存在本地，不纳入版本控制。
